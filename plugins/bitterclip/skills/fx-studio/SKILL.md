# Make an FX scene

Make the person's visual idea real in the shared FX Studio, then improve the same scene from feedback. Distinguish source authoring from applying an effect to a production. Do not turn an FX request into a Recording upload, Clip edit, or Render.

Use the connected BitterClip tools. Open `fx_studio_open` early on the relevant saved scene and keep that view open through reads, writes and inspections; it is not a last-step `workspace_open` handoff. For a new scene, open the library, then confirm the same view targets the returned scene ID after the first save; an unrelated previously selected effect is not the new one. Preserve the open view's playback/inspection posture through revisions. Opening is read-only. If the host cannot display the app, give the returned `studio_url` without claiming it opened visibly. If tools are missing or have stale argument shapes, refresh/reconnect the existing connector and start a fresh conversation when appropriate; do not guess calls or pretend a local file edit changed the live scene.

Before substantial source authoring, call `help` with the exact `bitterclip://docs/identity-scene-authoring` URI. Use current tool descriptors for arguments and recovery, rather than copying a schema into chat. Ask only for creative choices that materially affect the requested result. Preserve the person's style: a request for richer depth, stronger motion, or more expressive type is not an invitation to impose a minimal style or ban 3D.

An FX scene is an ES module, not a template parameter set. Export `scene` with the saved `scene_id`, `mount(ctx)`, `reset(ctx)`, and `frame(ctx)`; mount under `ctx.layer` and return a refs object containing a root HTMLElement. `frame(ctx)` receives that object as `ctx.refs`, not `ctx.refs.refs`. HTML/CSS, SVG, Canvas, and WebGL are options. Derive visible state from `ctx.elapsedMs` for repeatable forward and backward seeking. Use fixed-step playback for a stateful simulation only when its reset and replay are deterministic. CSS animation/transition clocks, wall time, ambient randomness, imports and network fetches are not substitutes for the supplied clock and admitted assets. Standalone FX has no audio; do not promise a soundtrack or sync without a separately supported production path.

Create with `scene_write` and `expected_revision: 0`. For an existing scene, read its current source and revision/SHA first. Keep the same scene ID for ordinary feedback; use guarded `scene_edit` for a unique literal replacement or guarded `scene_write` for a coherent full-source revision. Adopt the returned revision and SHA. On a stale guard, reread and reconcile the person's requested change with the current source; never blindly retry or overwrite another draft. A failed write is not a saved revision. Use `identity_asset_ingest` only when the person supplies or authorizes a needed image/texture, then declare returned IDs in saved `settings.asset_ids`; scene code has no ambient asset access.

Keep the work legible while it evolves: briefly describe the visual idea, the meaningful revision, and what is actually saved. Inspect `scene_preview` PNGs at useful times, including before and after the changed movement or hold. Match each preview's scene ID, revision and source SHA to the saved receipt before crediting it to the new version. Check the open Studio's current preview as available; a last-good older preview is not proof that the new source runs. If an embedded card's reads fail or it stays on an older revision, make one bounded recovery attempt and use the exact first-party Studio view if available; distinguish that view from the stale card. Seek backward and replay when motion or statefulness matters. If the candidate fails preview, keep its readable source and the last working display distinct, diagnose the runtime error, repair the same scene, and inspect again. Still frames do not prove played motion, sound, or an Export.

Stop at a source-only scene when that is what the person asked for. Saving or previewing does not change a Project default, Episode, Clip, or admitted Export. Never change account or Project defaults merely to satisfy a one-Clip request.

When asked for a new Clip containing this saved scene, follow the Clip skill for source-backed selection and `clip_create`, then read that exact Clip. Before inserting anything, discover a compatible preset and supported layout/sound values from the current live identity catalog/docs or returned asset listings; never invent IDs. If required values are not exposed, stop without inserting a provisional block or routing through `identity_apply_to_project`. One model-visible composition-scoped route is conditional: use `episode_fx_insert` to place a supported opener/outro block template on the Clip, reread its revision and exact inserted occurrence, and use `episode_edit` `identity_part.replace` on that occurrence only if `episode_read` advertises `identity_replace`. The replacement configuration is `{preset_id, params: {signature_lab: {scene, layout, sound, duration_ms?}}}`: `scene` is the saved scene ID. Omit optional duration unless needed; do not let the provisional template dictate the authored scene's visual style. This replaces the provisional block on the same Clip, not the Project's defaults. Reread: the replacement may change the occurrence capability from `identity_replace` to `identity_customize`; `identity_customization` is its state payload, not a capability. A `preparing` bake is not a failed write; follow its bounded status/read continuation, then render or retry the exact render only when the returned status makes that safe, without duplicating insertion, replacement or Render. On terminal failure or unknown settlement, report the exact blocker. Account for FX duration in the Clip's actual total and verify its exact Export through the Clip skill when requested. If the host lacks these model-visible tools or the replacement capability, stop with the saved scene and explain that scoped application is unverified; do not use the app-only full editor operation or claim the scene appears in the Clip.

Later scene feedback changes source on the same scene, not the frozen scene bytes already used by a Clip or its earlier Export. If the person also wants that Clip updated, read its current head and scene-backed occurrence; where `identity_customize=true` is advertised, inspect the `identity_customization` state payload and use revision-guarded `episode_edit` `identity_part.customize` with `set.params.signature_lab` carrying the supported recipe, even when the declarative recipe values are unchanged. Reread the settled Clip. Feedback on a delivered Export retains private render intent: render the new exact revision without extra confirmation unless the person says draft-only, review-first or no render. Retain the earlier Export. If the host cannot expose the current Clip, capability or supported recipe, do not claim the new scene revision has propagated to video.
